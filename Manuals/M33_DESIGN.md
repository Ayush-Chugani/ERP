# M33 blueprint and schema review (prompts 1?2)

M32 is implemented and verified. M33 owns centralized evidence metadata, immutable versions, tags and audit, and reuses M13 FileObject/private storage/scanner and M15 scoped permissions. It does not replace or reinterpret existing ActivityAttachment records. A controlled legacy importer will create new evidence aggregates with provenance rather than silently adopting historical attachments.

## Model ownership and baseline

The supplied five source tables are evidence_document (metadata/workflow/soft deletion), evidence_document_version (file references and version sequence), evidence_tag (shared taxonomy), evidence_document_tag (composite PK association), evidence_document_audit (append-only action history). Existing references: staff_activities.StaffActivity, accounts.User/user_account, common_reference.DocumentType, academic_calendar.AcademicYear, staff_profile.ExternalOrganization/VerificationStatus/ApprovalStatus, documents_exit.FileObject. Missing shared masters EvidenceType and ConfidentialityLevel are added to staff_profile using exact source DDL; no existing model is duplicated.

All source columns, key widths, nullability, lengths, date/version checks, version/document/file uniqueness and FK targets are retained. PROTECT maps application deletion to the source restrict behavior. Source DATE/DATETIME/TIMESTAMP/JSON/native TEXT/ENUM fields use established native field classes. Django composite PK maps the document/tag table without an invented ID. Native installers refuse silently adopting pre-existing tables and reversal of populated records.

The version table receives one documented generated nullable BIGINT UNSIGNED column: current_document_id = CASE WHEN is_current THEN evidence_document_id ELSE NULL END, UNIQUE. This guarantees at most one current version; parent row locks, current-version verification and post-command invariant checks guarantee exactly one after successful create/replace. The parent current_version_number must match that row. Replacement marks the previous version non-current and inserts the next positive unsigned SMALLINT version, never overwriting a file. Native triggers forbid historical content-field mutation, false-to-true reactivation and deletion; only current-to-historical demotion is allowed. Audit rows reject UPDATE/DELETE. No broad speculative performance indexes are added before evaluating FK/unique indexes and actual query plans.

## App and request flow

App evidence: models/fields; frozen migrations; permissions/selectors; validators/forms; transactional services/audit; strict serializers/API/URLs; readonly operational admin and governed tag administration; management commands for seed, expiry alerts, integrity/health and legacy import; React/MUI PWA console following the established project architecture; backend concurrency/security tests and frontend MSW/component acceptance tests. Server-side ModelForms reuse validators, but persistence must use services; no duplicate server-rendered application is introduced.

Create-with-file: fresh principal and M33 scoped rights -> lock authorized live staff_activity -> validate active masters, metadata/dates/classification and tags -> M13 durable file transaction validates content/size/scanner, writes private random key and FileObject -> create document + version 1 + tag links + CREATE/UPLOAD source and M15 audits + actor-bound receipt atomically. Any failure rolls back rows and removes the new file using M13 cleanup. Existing bounded M13 safe PDF/PNG/JPEG pipeline is retained; Office/archive/script types remain rejected. Scanning is synchronous and fail-closed: infected/unknown/failed scans never enter the accessible evidence store; rejection telemetry and scanner remediation replace a new unneeded pending-file schema.

Replacement: lock parent document and current version, reauthorize FILE.UPDATE and metadata scope, verify optimistic token and idempotency key, write a new FileObject, demote old current version, insert next version, reset verification to PENDING and approval to DRAFT and clear their actors/timestamps/remarks/reasons, update parent pointer and audit REPLACE/UPLOAD. This reset prevents a previous approval from certifying new content. Previous versions remain immutable and require HISTORY.READ plus current document/file confidentiality and file rights. Metadata changes are restricted to draft/rejected evidence and are audited with before/after changed-field JSON; security and workflow fields cannot be patched. Ownership never changes.

## Workflow, access and audit decisions

New evidence begins verification PENDING, approval DRAFT. Explicit verify/reject-verification operate on permitted pending/rejected records. Approval requires VERIFIED by default; rejection requires a reason and clears approval actors/timestamps. Independent verification/approval excludes creator, uploader and activity subject by default; an explicit setting may allow self verification after institutional review. No user is automatically granted rights. Replacement policy always invalidates old workflow. Metadata update cannot lower confidentiality without explicit classification-management rights.

Permissions use M15 EVIDENCE resources DOCUMENT (CRUD/VERIFY/APPROVE/EXPORT), FILE (READ for preview/download, CREATE/UPDATE), HISTORY.READ, AUDIT.READ, TRASH.READ/UPDATE, TAG.UPDATE and CLASSIFICATION.UPDATE; classified metadata also requires the configured LEVEL_<code>.READ scope. PUBLIC/INTERNAL still require authenticated scoped DOCUMENT.READ. Unknown/inactive classifications deny. Staff activity supplies institution/campus/department/subject ownership; independent central M33 grants deliberately authorize cross-module evidence without granting access to unrelated subtype data. FILE rights are separate so reviewers can see permitted metadata without file access. Every binary request additionally uses the M13 file-level and institution policy. Admin is read-only for documents/versions/audits and applies the same scopes/classification. No superuser bypass is introduced for M33.

Source audit actions cover CREATE, UPLOAD, REPLACE, UPDATE_METADATA, PREVIEW, DOWNLOAD, VERIFY, REJECT_VERIFICATION, APPROVE, REJECT_APPROVAL, SOFT_DELETE, RESTORE and ACCESS_DENIED. Successful audit failure aborts mutation or file delivery. Denials are recorded separately after the failed business transaction when the document exists; callers receive the same unavailable response and never see storage keys. Audit access requires AUDIT.READ plus document scope/classification. Operational logs contain IDs, action, outcome, duration and correlation only, never metadata/file contents or private paths. IP/user-agent fields are bounded; forwarded addresses are not trusted automatically.

Soft deletion preserves files, versions, tags, workflow and audits, setting deleted_at/by/reason and is_active false. Restore requires TRASH.UPDATE, clears deletion metadata and reactivates only when its staff activity remains available. Ordinary selectors exclude deleted evidence; authorized trash selectors are separate. Idempotent retries reauthorize current permissions and compare request digest; stale optimistic updates return conflict.

## Discovery, expiry, imports and PWA

Search/filter/queues/report/export scope before exposing metadata. Bound pages to 100, large reference searches to minimal labels, CSV rows to 10,000 and use streaming/keyset batches. SQL counts and version/access aggregates avoid join multiplication. Tags are normalized codes with controlled active/inactive administration, and replacements preserve tags.

Expiry commands use explicit as-of date and configured thresholds (90/60/30/7 days), authorized actor and an optional disabled notification adapter. A durable deduplication/outbox record tracks document/expiry/threshold and delivery attempts; adapters receive only stable IDs and must resolve current authorized recipients. Missing-expiry policy is configured by document type code and defaults empty. No external messages are sent by implementation.

Legacy import is explicit, bounded and resumable by operator-supplied source identifiers and content digests. Dry-run validates mappings, authorized staff activities, metadata, source containment, file signatures/scanner and duplicate keys without writing business rows/files. Actual rows use the same creation service and append provenance with trustworthy original timestamps retained as provenance, never backdating authoritative audit. Already imported identical source rows replay safely; changed source keys conflict. No automatic deletion/rollback of historical files is provided.

PWA uses existing static precache and authenticated NetworkOnly; no document/audit/metadata cache or offline upload queue. Drafts remain only in memory. Responsive accessible forms support error focus, version/history navigation, workflow, audit, tags and trash/restore with explicit offline indicators. Inline previews are limited to safe PDF/images with no-store, nosniff, sandbox CSP and frame restrictions; otherwise attachment. Proxy streaming is used rather than signed redirects so authorization/revocation stays at the application boundary.

## Compatibility finding during native migration validation

The supplied baseline declares user-account foreign keys BIGINT UNSIGNED, but this established Django project uses signed BigAutoField for user_account.user_id (M15 compatibility intentionally retained AbstractUser IDs). MySQL rejects unsigned-to-signed FKs. M33 therefore maps only its *_user_id columns to signed BIGINT, matching the existing User model and earlier platform integrations. Activity/document/version/file keys remain unsigned. No existing user table is altered. The frozen installed DDL and schema inventory record this explicit compatibility adaptation; existing-table adoption must check it. The initial validation attempt failed on the first evidence CREATE TABLE, before any evidence table was created; the shared master migration completed normally.
