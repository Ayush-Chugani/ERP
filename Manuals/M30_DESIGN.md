# M30 design and integration map

The supplied prompt pack is the requirements source; implementation follows prompts 1-15. Its ten-column staff_award table and the canonical award_category master remain authoritative. Existing M29 implementation is complete locally; M30 does not alter its data.

Reuse StaffActivity ownership and statuses, EmployeeAssignment dated authorization, M15 permission evaluation and append-only audit, shared staff-activity workflow/command receipts, M13 private scanned evidence, and the existing React/MUI/PWA shell. Add apps.awards, AwardCategory under staff_profile, and a separate append-only platform_awards_status_history. No child ownership, status or file columns. Exact frozen MySQL DDL uses unsigned FK types, CHAR(3), DECIMAL(14,2), source CHECKs, InnoDB and utf8mb4. Existing tables require explicit adoption review; populated reversal is refused.

AWARD_RECOGNITION is the source activity type, in group AWARD. Required award_date selects the immutable dated parent assignment context; creation may omit context_date (derived from award_date), and supplied context_date must match. Date/ownership corrections require recreating a draft under the correct context. Editable states are DRAFT/RETURNED; independent reviewers verify and approve. Nullable category/organization must be active when supplied.

Money is nullable, nonnegative, exact decimal with 14 digits and two decimal places. JSON floats are rejected; API responses and frontend edits use strings. Null means unspecified and differs from zero. Currency is normalized to three uppercase ASCII letters, defaults INR, and is never converted or summed across currencies. Financial summaries aggregate cash prize and incentive separately per currency. No assumed exchange rates or institutional incentive rules.

Permission matrix: AWARDS.ACTIVITY.READ lists/details; CREATE requires dated assignment scope and READ; UPDATE edits/submits eligible records; VERIFY reviews/returns/verifies independently; APPROVE approves/rejects independently; DELETE archives eligible records; EXPORT intersects READ scope. SELF, department, campus, institution and global scopes reuse M15; DENY wins. AWARDS.MASTER.UPDATE at GLOBAL maintains shared category master without deletion. Private evidence additionally requires M13 confidentiality permissions. StaffAward Django admin is scoped and read-only; AwardCategory admin requires AWARDS.MASTER.UPDATE and audits all changes, with deletion disabled.

PWA uses existing NetworkOnly API policy. Drafts stay in component memory; offline writes are disabled; retries use stable request keys and optimistic versions. Runtime and event delivery remain disabled until deployment configuration is supplied. No grants or outbound notifications are installed automatically.
