1. Module Objective and Architecture Context
This module records awards, honours, recognitions, prizes and institutional acknowledgements received by staff. It is implemented as a specialized child record of the common staff_activity entity, ensuring that shared workflow, ownership, document evidence, status, audit and reporting capabilities can remain centralized.
The child table uses staff_activity_id as both its primary key and foreign key. This should be represented in Django as a one-to-one relationship with primary_key=True (or an equivalent domain pattern already used by the SIMS project). The module must not create a second independent activity identity.
award_category_id and awarding_organization_id are master-data relationships. The implementation should prefer selectable master records, with controlled creation or lookup workflows rather than free-text duplication.

3. Authoritative MySQL Table Definition
CREATE TABLE staff_award (
    staff_activity_id BIGINT UNSIGNED PRIMARY KEY,
    award_category_id SMALLINT UNSIGNED NULL,
    award_name VARCHAR(500) NOT NULL,
    awarding_organization_id BIGINT UNSIGNED NULL,
    award_date DATE NOT NULL,
    citation_details TEXT NULL,
    cash_prize_amount DECIMAL(14,2) NULL,
    incentive_amount DECIMAL(14,2) NULL,
    currency_code CHAR(3) NOT NULL DEFAULT 'INR',
    award_reference_number VARCHAR(150) NULL,
    CONSTRAINT chk_staff_award_amounts CHECK (
        (cash_prize_amount IS NULL OR cash_prize_amount >= 0)
        AND (incentive_amount IS NULL OR incentive_amount >= 0)
    ),
    CONSTRAINT fk_staff_award_activity FOREIGN KEY (staff_activity_id)
        REFERENCES staff_activity(staff_activity_id),
    CONSTRAINT fk_staff_award_category FOREIGN KEY (award_category_id)
        REFERENCES award_category(award_category_id),
    CONSTRAINT fk_staff_award_org FOREIGN KEY (awarding_organization_id)
        REFERENCES external_organization(organization_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
COLLATE=utf8mb4_unicode_ci;
