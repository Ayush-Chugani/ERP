13 - Document, Certificate and Exit
Architecture
Django modular monolith with plugin-ready app boundaries
Authorization
Existing custom user + role/permission model; no duplicate auth model
Database
MySQL / InnoDB / utf8mb4; schema-first compatibility

Service-layer business rules, thin APIs/views, transaction-safe workflows
Primary Goal
Implement secure student documents, certificate lifecycle, and exit processing

Purpose of this pack
Use the prompts in sequence to implement Module 13 without weakening the previously established SIMS architecture. Each prompt is designed to be pasted into an AI coding assistant together with the current repository context. The prompts explicitly protect existing schema ownership, custom-user authorization, auditability, and cross-module references.
Non-negotiable implementation principles
Preserve the supplied SQL semantics. Do not rename tables/columns or silently change nullability, uniqueness, enums, or foreign keys.
Reuse existing Student, Document Type, Programme Enrolment, and custom User/Role/Permission models. Never create shadow master tables.
Keep business rules in services/use-cases; keep serializers/forms/views thin; use atomic transactions for state-changing workflows.
Treat uploaded files as sensitive objects: validate type/size, generate server-side names, avoid trusting client paths/URLs, and enforce authorization before download.
Make certificate issue and student-exit operations idempotent, auditable, permission-checked, and safe under concurrent requests.
Use soft deletion only where the supplied schema supports it (`file_object.deleted_at`); do not pretend hard-deleted business records still exist.
Use migrations compatible with MySQL and the project migration history. Any unavoidable schema deviation must be clearly documented before implementation.

Appendix A - Source SQL Schema (Implementation Baseline)
The following schema is the baseline supplied for Module 13. Implementation prompts above assume these columns and relationships remain authoritative unless a separately approved schema migration changes them.
-- =============================================================
-- 13. DOCUMENT, CERTIFICATE AND EXIT MODULE
-- =============================================================
CREATE TABLE file_object (
    file_object_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    storage_provider VARCHAR(30) NOT NULL,
    storage_key VARCHAR(500) NOT NULL UNIQUE,
    original_file_name VARCHAR(255) NOT NULL,
    mime_type VARCHAR(100) NOT NULL,
    file_size_bytes BIGINT UNSIGNED NOT NULL,
    checksum_sha256 CHAR(64) NULL,
    stored_file_name VARCHAR(255) NULL,
    storage_url VARCHAR(1000) NULL,
    file_extension VARCHAR(20) NULL,
    confidentiality_level ENUM('PUBLIC','INTERNAL','CONFIDENTIAL','RESTRICTED','HIGHLY_RESTRICTED') NOT NULL DEFAULT 'INTERNAL',
    is_encrypted BOOLEAN NOT NULL DEFAULT FALSE,
    uploaded_by_user_id BIGINT UNSIGNED NULL,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL,
    CONSTRAINT chk_file_object_size CHECK (file_size_bytes > 0),
    CONSTRAINT chk_file_object_checksum CHECK (checksum_sha256 IS NULL OR checksum_sha256 REGEXP '^[0-9A-Fa-f]{64}$')
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE student_document (
    student_document_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    student_id BIGINT UNSIGNED NOT NULL,
    document_type_id SMALLINT UNSIGNED NOT NULL,
    file_object_id BIGINT UNSIGNED NOT NULL,
    document_number VARCHAR(100) NULL,
    issue_date DATE NULL,
    expiry_date DATE NULL,
    verification_status ENUM('PENDING','VERIFIED','REJECTED','EXPIRED') NOT NULL DEFAULT 'PENDING',
    verified_at DATETIME NULL,
