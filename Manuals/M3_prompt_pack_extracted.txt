How to use this prompt pack
This pack converts the supplied Academic Calendar schema into a controlled sequence of prompts for an AI coding assistant or development team. Use Prompt 0 once to establish the architectural contract. Then execute Prompts 1 through 13 in order. Each prompt asks for bounded outputs, tests, and explicit assumptions so the module can be reviewed before the next implementation increment.
1.  Paste Prompt 0 together with the authoritative SQL baseline into the implementation conversation.
2.  Run one numbered prompt at a time and review its deliverables and acceptance criteria.
3.  Require migrations and tests to pass before moving to the next prompt.
4.  Keep module boundaries intact. Cross module data must be referenced through stable contracts, not copied.
5.  Record approved schema refinements in an architecture decision record before changing the baseline.
Architecture invariants
The system remains a plugin-ready modular monolith. Academic Calendar is an internal Django app with explicit public services and API contracts.
Authentication uses Django with a custom User model defined from the beginning. Do not create a parallel password, session, group, or permission system.
Authorization extends Django permissions with institution membership, institution-scoped roles, campus or department scope, module activation, workflow authority, confidentiality, and record-level access.
MySQL 8.0.16 or later is the persistence baseline. Database constraints and application validation must reinforce each other.
All writes that change calendar state are transactional, auditable, idempotent where appropriate, and safe under concurrent requests.
API and UI behavior must be institution-aware and timezone-aware. Never trust a client-supplied institution or campus identifier without authorization checks.

Schema review decisions to make explicitly
The supplied DDL is the baseline, but implementation must explicitly decide the following before production migration. These are review questions, not silent changes.
Tenant ownership: academic_year and academic_term currently have no institution_id. Confirm whether calendars are globally shared or institution-owned. A multi-client SIMS usually requires institution ownership and institution-scoped uniqueness.
Term containment: validate that term dates and registration dates fall within the parent academic year, not merely that each local range is ordered.
Active-period cardinality: decide whether one institution may have only one ACTIVE academic year and whether overlapping terms of the same type are permitted.
Time-slot overlap: decide whether non-break teaching slots may overlap within one campus. MySQL CHECK constraints cannot enforce interval overlap across rows, so a transactional service rule is required.
Deletion policy: choose PROTECT or RESTRICT for referenced calendar records. Closed or used periods should normally be immutable and never cascaded away.
Timezone semantics: TIME stores wall-clock time without timezone. Confirm that campus timezone is available and used when constructing datetimes.

Authoritative SQL baseline
CREATE TABLE academic_year (
    academic_year_id SMALLINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    year_code VARCHAR(9) NOT NULL UNIQUE,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status ENUM('PLANNED','ACTIVE','CLOSED') NOT NULL DEFAULT 'PLANNED',
    CONSTRAINT chk_academic_year_dates CHECK (end_date > start_date)
);
 
CREATE TABLE academic_term (
    academic_term_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    academic_year_id SMALLINT UNSIGNED NOT NULL,
    term_code VARCHAR(20) NOT NULL,
    term_name VARCHAR(100) NOT NULL,
    term_type ENUM('ODD','EVEN','SUMMER','ANNUAL','OTHER') NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    registration_start_date DATE NULL,
    registration_end_date DATE NULL,
    status ENUM('PLANNED','REGISTRATION_OPEN','ACTIVE','CLOSED') NOT NULL DEFAULT 'PLANNED',
    CONSTRAINT uq_term_code UNIQUE (academic_year_id, term_code),
    CONSTRAINT chk_term_dates CHECK (end_date >= start_date),
    CONSTRAINT chk_term_registration_dates CHECK (
        registration_start_date IS NULL OR registration_end_date IS NULL
        OR registration_end_date >= registration_start_date
    ),
    CONSTRAINT fk_term_academic_year FOREIGN KEY (academic_year_id)
        REFERENCES academic_year(academic_year_id)
);
 
CREATE TABLE semester (
    semester_id TINYINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    semester_number TINYINT UNSIGNED NOT NULL UNIQUE,
    semester_name VARCHAR(50) NOT NULL UNIQUE,
    CONSTRAINT chk_semester_number CHECK (semester_number > 0)
);
 
CREATE TABLE time_slot (
    time_slot_id SMALLINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    campus_id SMALLINT UNSIGNED NOT NULL,
    slot_code VARCHAR(20) NOT NULL,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    is_break BOOLEAN NOT NULL DEFAULT FALSE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    CONSTRAINT uq_time_slot UNIQUE (campus_id, slot_code),
    CONSTRAINT chk_time_slot CHECK (end_time > start_time),
    CONSTRAINT fk_time_slot_campus FOREIGN KEY (campus_id)
        REFERENCES campus(campus_id)
);
