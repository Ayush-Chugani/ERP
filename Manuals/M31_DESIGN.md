# M31 design (Prompt 1)

Reuse M30 staff activity ownership, dated EmployeeAssignment, shared M15 workflow/RBAC/audit, M13 evidence, existing React/MUI/PWA and CSV conventions. Implement apps.professional_memberships with canonical eleven-column StaffProfessionalMembership and missing MembershipType in staff_profile. Reuse ExternalOrganization, RoleType and ParticipationLevel. Freeze source DDL; preserve five FKs, nullable organization-scoped unique number, date CHECK and native ENUM. Only the established separate approval-history extension is added. No silent table adoption; populated reverse is refused.

Application rules: trim blank numbers to NULL; database collation determines case-insensitive uniqueness within organization. Multiple NULL numbers and the same number in different organizations remain valid. Start/expiry are optional; expiry cannot precede start. Lifetime flag normalizes status to LIFETIME, but supplied expiry or renewal=True is rejected. LIFETIME status without the flag is rejected. Explicit mark-lifetime clears expiry/renewal. Context date derives from membership_start_date if supplied; otherwise a dated assignment context is required. Parent context/ownership remains immutable; membership dates may change within the retained ownership context when a draft is corrected or renewed.

Approval workflow is separate from membership_status. Draft/returned edits use UPDATE; CREATE requires READ too. Membership administrative status changes require VERIFY and READ, an eligible parent (DRAFT/RETURNED/APPROVED), an optimistic version and an idempotency key. Suspend: ACTIVE/EXPIRED to SUSPENDED; cancel: ACTIVE/EXPIRED/SUSPENDED to CANCELLED; reactivate: SUSPENDED/EXPIRED to ACTIVE only if not past expiry; mark-lifetime: ACTIVE/EXPIRED to LIFETIME. CANCELLED is terminal. No automatic reactivation, cancellation or suspension; the explicit expiry service only changes ACTIVE non-lifetime records to EXPIRED. Ordinary PATCH cannot bypass status actions. Initial historical administrative states require VERIFY.

Renewal window is configurable (default 30 days). renewal_due is derived, never an unsolicited write: renewal_required AND ACTIVE non-lifetime AND expiry in [today,today+window]. Reports also expose overdue and 30/60/90-day counts. Expiry command requires explicit actor, scoped VERIFY/READ, supports dry-run/as-of/chunking, and is disabled for applied changes unless its setting is enabled. No scheduler or outgoing messages are enabled automatically.

CSV import reuses scoped assignment IDs and master IDs, never guessed new organizations or activity IDs. Bounded 200-row/256KiB batches use common serializers/services, per-row savepoints and batch atomicity: report every invalid row, commit only when the whole batch is valid. Dry-run rolls all mutations/receipts/history back. Stable batch key + row index gives safe retries. Duplicates are rejected, never implicit updates. Audit stores row counts and field names, not file contents or membership numbers. Existing generic import conventions support CSV; XLSX conversion/design is documented rather than a second upload parser.

RBAC: PROFESSIONAL_MEMBERSHIPS.ACTIVITY READ/CREATE/UPDATE/DELETE/VERIFY/APPROVE/EXPORT, global MASTER.UPDATE. SELF, department, campus, institution and global scopes use M15 DENY precedence. Master admin uses guarded API/admin; transactional records are read-only in Django admin. Evidence additionally requires M13 confidentiality permissions. Membership actions and automatic expiry record before/after lifecycle values and actor in M15; history endpoint exposes sanitized audit to authorized READ scope. PWA caches static shell only; private membership APIs remain NetworkOnly, drafts in memory, offline writes disabled.

Native FK indexes and organization+number uniqueness are retained. EXPLAIN and query-count evidence precede any additional status/expiry indexes; no speculative source schema changes. Local implementation acceptance is separate from production enablement and device/volume acceptance.
