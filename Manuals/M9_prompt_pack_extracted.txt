How to use this pack
Run the prompts in sequence. Each stage assumes that earlier accepted outputs are available in the same working context. Review and commit one stage before moving to the next, especially where revised DDL, attendance policy, lesson-plan structure, or correction workflow affects later code.
Attach or paste the current repository tree, relevant settings, and upstream model definitions before Prompt 1.
Ask the implementation agent to identify assumptions and wait only when a missing decision changes data integrity, attendance calculation, or authorization.
Require runnable files, migrations, tests, commands, sample data, and verification evidence at every stage.
Keep institution and section scope server-controlled and treat marking, reopening, correction, export, and policy changes as auditable operations.
Use the final integrated build prompt only after the individual design decisions have been reviewed.

Common implementation context
Act as a senior full-stack Python web developer and software architect. Implement Module 9 of the SIMS platform as part of an enterprise plugin-ready modular monolith.
Use Django 5.x, Django REST Framework, MySQL 8.0.16 or later, React with TypeScript, Material UI, Vite, and @vite-pwa/plugin, with Gunicorn behind Nginx. The Django custom User model is the authentication authority. Retain the SIMS authorization extension for institution membership, scoped roles, campus and department scope, module activation, workflow authority, confidentiality, and record-level access.
Reuse the established institution, academic calendar, curriculum, student and staff, admission, term-registration, teaching-allocation, and timetable modules. Do not duplicate users, employees, rooms, courses, offerings, sections, rosters, timetable sessions, or academic periods. Derive ownership scope on the server, keep attendance and lesson-plan rules in explicit services, use transaction.atomic and select_for_update for collision-prone updates, and expose stable versioned APIs.
Cross cutting invariants
No session, roster row, faculty assignment, timetable occurrence, room, attendance record, or correction may cross institution scope through a client-supplied identifier.
A class session may reference only faculty and timetable records that belong to the same course-offering section and are valid on the session date.
Attendance may be recorded only for a roster membership valid for the same section and session date.
Bulk marking, finalization, reopening, and correction decisions must be atomic, idempotent, version-aware, and auditable.
Attendance calculations must use an explicit policy and remain historically reproducible after configuration changes.
Cancellation, rescheduling, timetable changes, roster changes, or status deactivation must not silently rewrite historical attendance.
Lesson plans must distinguish planned content from actual coverage and retain authorized revision history.
Students may view only their own permitted records; faculty and reviewers receive only their assigned and authorized scope.

-- =============================================================
-- 9. ATTENDANCE AND LESSON PLAN MODULE
-- =============================================================
 
CREATE TABLE class_session (
    class_session_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    course_offering_section_id BIGINT UNSIGNED NOT NULL,
    faculty_assignment_id BIGINT UNSIGNED NULL,
    timetable_session_id BIGINT UNSIGNED NULL,
    session_date DATE NOT NULL,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    room_id INT UNSIGNED NULL,
    session_type ENUM('LECTURE','TUTORIAL','PRACTICAL','PROJECT','SEMINAR','OTHER') NOT NULL,
    planned_topic TEXT NULL,
    topic_covered TEXT NULL,
    class_number SMALLINT UNSIGNED NULL,
    session_status ENUM('PLANNED','CONDUCTED','CANCELLED','RESCHEDULED') NOT NULL DEFAULT 'PLANNED',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_class_session_time CHECK (end_time > start_time),
    CONSTRAINT uq_class_session UNIQUE (course_offering_section_id, session_date, start_time),
    CONSTRAINT uq_class_session_owner UNIQUE (class_session_id, course_offering_section_id),
    CONSTRAINT fk_class_session_section FOREIGN KEY (course_offering_section_id) REFERENCES course_offering_section(course_offering_section_id),
    CONSTRAINT fk_class_session_faculty FOREIGN KEY (faculty_assignment_id) REFERENCES faculty_course_assignment(faculty_assignment_id),
    CONSTRAINT fk_class_session_timetable FOREIGN KEY (timetable_session_id) REFERENCES timetable_session(timetable_session_id),
    CONSTRAINT fk_class_session_room FOREIGN KEY (room_id) REFERENCES room(room_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
 
CREATE TABLE attendance_status (
    attendance_status_id TINYINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    status_code VARCHAR(20) NOT NULL UNIQUE,
    status_name VARCHAR(50) NOT NULL UNIQUE,
    counts_as_present BOOLEAN NOT NULL DEFAULT FALSE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
 
CREATE TABLE student_attendance (
    class_session_id BIGINT UNSIGNED NOT NULL,
    course_offering_section_student_id BIGINT UNSIGNED NOT NULL,
    course_offering_section_id BIGINT UNSIGNED NOT NULL,
    attendance_status_id TINYINT UNSIGNED NOT NULL,
    marked_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    marked_by_user_id BIGINT UNSIGNED NULL,
    remarks VARCHAR(500) NULL,
    PRIMARY KEY (class_session_id, course_offering_section_student_id),
    CONSTRAINT fk_student_attendance_session_owner FOREIGN KEY (class_session_id, course_offering_section_id)
        REFERENCES class_session(class_session_id, course_offering_section_id),
    CONSTRAINT fk_student_attendance_roster_owner FOREIGN KEY (course_offering_section_student_id, course_offering_section_id)
        REFERENCES course_offering_section_student(course_offering_section_student_id, course_offering_section_id),
    CONSTRAINT fk_student_attendance_status FOREIGN KEY (attendance_status_id) REFERENCES attendance_status(attendance_status_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
 
CREATE TABLE attendance_correction_request (
    attendance_correction_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    class_session_id BIGINT UNSIGNED NOT NULL,
    course_offering_section_student_id BIGINT UNSIGNED NOT NULL,
    old_status_id TINYINT UNSIGNED NOT NULL,
    requested_status_id TINYINT UNSIGNED NOT NULL,
    reason VARCHAR(1000) NOT NULL,
    request_status ENUM('PENDING','APPROVED','REJECTED','CANCELLED') NOT NULL DEFAULT 'PENDING',
    requested_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    resolved_at TIMESTAMP NULL,
    CONSTRAINT fk_attendance_correction_attendance FOREIGN KEY (class_session_id, course_offering_section_student_id)
        REFERENCES student_attendance(class_session_id, course_offering_section_student_id),
    CONSTRAINT fk_attendance_correction_old FOREIGN KEY (old_status_id) REFERENCES attendance_status(attendance_status_id),
    CONSTRAINT fk_attendance_correction_requested FOREIGN KEY (requested_status_id) REFERENCES attendance_status(attendance_status_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
