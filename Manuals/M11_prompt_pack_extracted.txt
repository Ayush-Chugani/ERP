1. How to Use This Prompt Pack
Use the prompts in sequence. Each prompt assumes the output from earlier prompts has been applied to the same codebase. The database schema is the authoritative business-data baseline, while implementation prompts add application-layer validation, authorization, auditing, API design, tests, and frontend behavior.

3. Schema Review and Required Implementation Decisions
The supplied SQL is coherent as a baseline, but several invariants are not expressible with the current columns alone. The implementation must make these decisions explicit rather than relying on UI behavior.
Finding
Risk
Implementation decision
MULTIPLE_CHOICE vs single feedback_choice_id
A response item can physically store only one selected choice.
Add a child table feedback_response_item_choice for selected choices; keep feedback_choice_id for SINGLE_CHOICE backward compatibility or phase it out in a controlled migration.
Answer-type exclusivity
choice, numeric_score and text_response can all be populated together.
Validate exactly the fields allowed by the question response_type; reject ambiguous payloads.
Choice/question ownership
A selected choice may belong to another question.
Validate selected choices belong to questionnaire_item.feedback_question.
Questionnaire item ownership
A response could reference an item from another questionnaire.
Validate item belongs to response.cycle.questionnaire.
Cycle scope / target shape
COURSE/FACULTY/PROGRAMME/etc. do not enforce which context FK is required.
Create a target-policy validator keyed by questionnaire_type.
Duplicate submission
No unique key prevents the same eligible respondent from submitting twice.
Use a privacy-safe eligibility/submission ledger or deterministic scope rule; do not expose identity in analytics.
Anonymous semantics
term_registration_id can identify the respondent even when questionnaire is anonymous.
Separate eligibility proof from analytic response identity; faculty result endpoints never return respondent identity fields.
Lifecycle immutability
Questionnaires can be edited after a cycle opens unless blocked by code.
Freeze questionnaire structure for OPEN/CLOSED cycles; use copy/version workflow for later edits.
