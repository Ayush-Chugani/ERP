Curriculum and Course Catalog Module Prompt Pack
Django 5  DRF  MySQL 8  React TypeScript PWA
Plugin ready modular monolith with a Django custom User model and institution scoped authorization extensions
SIMS Module 4  |  Implementation and verification prompts
Purpose and scope
This prompt pack converts the supplied Curriculum and Course Catalog schema into a disciplined implementation sequence for the existing Student Information Management System. It preserves the modular-monolith boundary, the custom Django User model, Django permissions, trusted institution context, institution-scoped roles, campus and department scope, module activation, workflow authority, confidentiality, and record-level access.
Use Prompt 0 once to establish the implementation contract. Execute Prompts 1 through 14 in order. Do not advance when migrations, automated tests, or architecture checks fail. Each implementation response must be bounded, name assumptions explicitly, and preserve stable public contracts between modules.
How to use this prompt pack
Provide the repository tree, relevant settings, and existing public interfaces for institution, department, programme, specialization, semester, authentication, and audit modules.
Run Prompt 0 at the start of the coding session, then submit one numbered prompt at a time.
Require the implementer to show files changed, migrations, tests, commands, authorization decisions, and unresolved risks.
Keep MySQL constraints for row-local invariants. Put cross-row, graph, lifecycle, overlap, and concurrency rules in transactional domain services with database locking where needed.
Reject direct cross-module model imports outside declared public interfaces, except in migrations or explicitly documented integration adapters.
Do not create microservices, a second user table, or a parallel RBAC store.
Architecture invariants
Invariant
Required interpretation
Deployment
One deployable Django modular monolith; curriculum is a bounded Django app, not a service.
Authentication
Use the project custom User model through settings.AUTH_USER_MODEL. Never introduce a second credential store.
Authorization
Combine Django permissions with active institution membership, institution-scoped roles, department/campus scope, module activation, workflow authority, confidentiality, and record rules.
Tenancy
Resolve institution from trusted membership and request context. Never trust institution, department, programme, or scope identifiers from payload alone.
Module boundary
Expose selectors, services, policies, DTOs, events, and URL contracts as the stable public interface.
Transactions
Use atomic services and select_for_update for activation, retirement, cloning, bulk mapping, and other race-sensitive operations.
Database
Target MySQL 8.0.16 or later with utf8mb4_unicode_ci, named constraints, indexed foreign keys, and deterministic migrations.
Frontend
React with TypeScript and MUI, integrated through DRF; PWA caching must not expose confidential or stale authorization-sensitive data.
Audit
Record actor, institution, action, object identity, before/after values, request correlation, and timestamp for governed changes.
Authoritative entity summary
Entity
Responsibility
course_category
Defines graded/GPA behavior and active catalog classifications.
course_catalog
Department-owned reusable course definition with type, hours, credits, validity, and default category.
curriculum_scheme
Effective-dated programme or specialization curriculum with lifecycle state and credit target.
curriculum_course
Places a course in a scheme and semester with requirement, elective, ordering, marks, passing, and duration metadata.
course_prerequisite
Directed course dependency with optional minimum grade; self-links and cycles are forbidden.
Schema review decisions to make explicitly
Decide whether course_code, category_code, category_name, and scheme_code are globally unique or institution-scoped. In a multi-client SIMS, global uniqueness is usually too restrictive unless codes are centrally governed.
Confirm the referenced programme_specialization table has a UNIQUE(specialization_id, programme_id) key in the same column order and compatible unsigned types; otherwise the composite foreign key cannot be created.
Add curriculum_scheme effective-date validation and define whether active date ranges may overlap for the same programme and specialization.
Prevent category drift: curriculum_course.course_category_id must either equal course_catalog.course_category_id or be documented as an intentional per-scheme override governed by policy.
Add nonnegative mark checks; require passing_marks to be between zero and internal_max_marks plus external_max_marks; define zero-total and pass/fail-only behavior.
Define elective semantics: mandatory rows normally have no elective_group_code; elective rows require a normalized, nonblank group code and group-level selection rules.
Verify semester ownership and range against the scheme programme rather than accepting any semester row.
Prevent prerequisite cycles and clarify whether prerequisites can cross departments, programmes, and effective-date boundaries.
Prefer immutable course identities and scheme versioning over destructive edits once referenced by offerings, registrations, assessments, or results.
Define delete behavior explicitly. Governed catalog and curriculum records should normally be retired or deactivated, not cascade-deleted.
Authoritative SQL baseline
Treat the following DDL as the supplied baseline. Prompt 1 must assess it against the full SIMS schema before migrations are generated. Do not silently change identifiers or business meaning.
CREATE TABLE course_category (    course_category_id SMALLINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,    category_code VARCHAR(30) NOT NULL UNIQUE,    category_name VARCHAR(100) NOT NULL UNIQUE,    is_graded BOOLEAN NOT NULL DEFAULT TRUE,    contributes_to_gpa BOOLEAN NOT NULL DEFAULT TRUE,    is_active BOOLEAN NOT NULL DEFAULT TRUE) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
CREATE TABLE course_catalog (    course_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,    owning_department_id SMALLINT UNSIGNED NOT NULL,    course_category_id SMALLINT UNSIGNED NOT NULL,    course_code VARCHAR(30) NOT NULL UNIQUE,    course_title VARCHAR(200) NOT NULL,    short_title VARCHAR(80) NULL,    course_type ENUM('THEORY','LAB','THEORY_LAB','PROJECT','SEMINAR','INTERNSHIP','OTHER') NOT NULL,    lecture_hours DECIMAL(4,1) NOT NULL DEFAULT 0,    tutorial_hours DECIMAL(4,1) NOT NULL DEFAULT 0,    practical_hours DECIMAL(4,1) NOT NULL DEFAULT 0,    self_study_hours DECIMAL(4,1) NOT NULL DEFAULT 0,    credits DECIMAL(4,1) NOT NULL DEFAULT 0,    effective_from DATE NULL,    effective_to DATE NULL,    is_active BOOLEAN NOT NULL DEFAULT TRUE,    CONSTRAINT chk_course_nonnegative_values CHECK (lecture_hours >= 0 AND tutorial_hours >= 0        AND practical_hours >= 0 AND self_study_hours >= 0 AND credits >= 0),    CONSTRAINT chk_course_effective_dates CHECK (effective_from IS NULL OR effective_to IS NULL        OR effective_to >= effective_from),    CONSTRAINT fk_course_department FOREIGN KEY (owning_department_id) REFERENCES department(department_id),    CONSTRAINT fk_course_category FOREIGN KEY (course_category_id) REFERENCES course_category(course_category_id)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
CREATE TABLE curriculum_scheme (    curriculum_scheme_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,    programme_id SMALLINT UNSIGNED NOT NULL,    specialization_id SMALLINT UNSIGNED NULL,    scheme_code VARCHAR(30) NOT NULL UNIQUE,    scheme_name VARCHAR(150) NOT NULL,    regulation_year YEAR NOT NULL,    total_credits DECIMAL(6,1) NULL,    effective_from DATE NOT NULL,    effective_to DATE NULL,    status ENUM('DRAFT','ACTIVE','RETIRED') NOT NULL DEFAULT 'DRAFT',    CONSTRAINT fk_scheme_programme FOREIGN KEY (programme_id) REFERENCES programme(programme_id),    CONSTRAINT fk_scheme_specialization_programme FOREIGN KEY (specialization_id, programme_id)        REFERENCES programme_specialization(specialization_id, programme_id)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
CREATE TABLE curriculum_course (    curriculum_course_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,    curriculum_scheme_id INT UNSIGNED NOT NULL,    semester_id TINYINT UNSIGNED NOT NULL,    course_id INT UNSIGNED NOT NULL,    course_category_id SMALLINT UNSIGNED NOT NULL,    is_mandatory BOOLEAN NOT NULL DEFAULT TRUE,    elective_group_code VARCHAR(30) NULL,    display_order SMALLINT UNSIGNED NULL,    internal_max_marks DECIMAL(6,2) NOT NULL DEFAULT 0,    external_max_marks DECIMAL(6,2) NOT NULL DEFAULT 0,    passing_marks DECIMAL(6,2) NULL,    exam_duration_minutes SMALLINT UNSIGNED NULL,    CONSTRAINT uq_curriculum_course UNIQUE (curriculum_scheme_id, semester_id, course_id),    CONSTRAINT fk_curriculum_course_scheme FOREIGN KEY (curriculum_scheme_id) REFERENCES curriculum_scheme(curriculum_scheme_id),    CONSTRAINT fk_curriculum_course_semester FOREIGN KEY (semester_id) REFERENCES semester(semester_id),    CONSTRAINT fk_curriculum_course_course FOREIGN KEY (course_id) REFERENCES course_catalog(course_id),    CONSTRAINT fk_curriculum_course_category FOREIGN KEY (course_category_id) REFERENCES course_category(course_category_id)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
CREATE TABLE course_prerequisite (    course_id INT UNSIGNED NOT NULL,    prerequisite_course_id INT UNSIGNED NOT NULL,    minimum_grade VARCHAR(5) NULL,    PRIMARY KEY (course_id, prerequisite_course_id),    CONSTRAINT chk_prerequisite_not_self CHECK (course_id <> prerequisite_course_id),    CONSTRAINT fk_prerequisite_course FOREIGN KEY (course_id) REFERENCES course_catalog(course_id),    CONSTRAINT fk_prerequisite_required FOREIGN KEY (prerequisite_course_id) REFERENCES course_catalog(course_id)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
