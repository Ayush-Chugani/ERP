SIMS – Module 28Co-Curricular Activities
Enterprise Implementation Prompt Pack
A sequential AI prompt pack for implementing the Co-Curricular Activities module in the Staff Information Management System (SIMS), with enterprise-grade Django, Django REST Framework, MySQL, React/TypeScript, and Progressive Web App architecture.
1. Source Database Contract
CREATE TABLE cocurricular_activity (    staff_activity_id BIGINT UNSIGNED PRIMARY KEY,    cocurricular_category_id SMALLINT UNSIGNED NOT NULL,    event_name VARCHAR(500) NOT NULL,    organizer_id BIGINT UNSIGNED NULL,    institution_organization_id BIGINT UNSIGNED NULL,    event_date DATE NULL,    venue_name VARCHAR(250) NULL,    city VARCHAR(120) NULL,    state_id SMALLINT UNSIGNED NULL,    country_id SMALLINT UNSIGNED NULL,    achievement_award VARCHAR(500) NULL,    contribution_details TEXT NULL,    CONSTRAINT fk_cocurricular_activity_parent FOREIGN KEY (staff_activity_id) REFERENCES staff_activity(staff_activity_id),    CONSTRAINT fk_cocurricular_activity_category FOREIGN KEY (cocurricular_category_id) REFERENCES cocurricular_category(cocurricular_category_id),    CONSTRAINT fk_cocurricular_activity_organizer FOREIGN KEY (organizer_id) REFERENCES organizer(organizer_id),    CONSTRAINT fk_cocurricular_activity_org FOREIGN KEY (institution_organization_id) REFERENCES external_organization(organization_id),    CONSTRAINT fk_cocurricular_activity_state FOREIGN KEY (state_id) REFERENCES state(state_id),    CONSTRAINT fk_cocurricular_activity_country FOREIGN KEY (country_id) REFERENCES country(country_id)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
2. Core Architecture Rules
Treat cocurricular_activity as a strict one-to-one subtype of staff_activity; staff_activity_id is both primary key and foreign key.
Reuse existing SIMS authentication, RBAC, approval workflow, audit trail, master data, evidence/attachments, notifications, and reporting.
Create/update parent and subtype records atomically; never leave partial records.
Preserve SQL field lengths, NULL semantics, referential integrity, utf8mb4, and MySQL compatibility.
Enforce authorization on the server and object level; UI visibility alone is never security.
Build mobile-first accessible React UI and safe PWA caching that does not expose sensitive API data.
Optimize list/report queries with measured indexes, select_related/prefetch_related, and pagination.
3. Sequential Development Prompts
Run these prompts in sequence. For each stage, require the coding assistant to inspect existing project conventions before introducing new abstractions.

Inspect the existing SIMS repository before writing code. Identify StaffActivity, Employee/User ownership, activity types, academic-year/institution/campus/department masters, authentication, RBAC, approval workflow, audit logging, evidence subsystem, notifications, reporting, API conventions, React routing/state/form libraries, service worker, and tests. Define required/optional rules, country-state consistency, date consistency, duplicate detection, ownership, lifecycle status, and editability after submission/approval. Prompt 03 — Django ORM and Migration
Implement the Django model with db_table="cocurricular_activity". Map staff_activity_id as a OneToOneField primary key without creating a duplicate *_id column. Map all foreign keys to existing master models with correct db_column, null/blank, max_length, and on_delete behavior. Create a safe MySQL migration or migration-state alignment if the table already exists. Review useful indexes based on actual filters, include rollback steps, and avoid redundant indexes.
Prompt 04 — Atomic Service Layer
Implement create/update/submit/review/archive operations in a reusable domain service. Use transaction.atomic() for StaffActivity plus CoCurricularActivity changes, validate activity type and ownership, enforce workflow state, and use select_for_update() where concurrent review/editing could race. Keep API views thin. Never allow a failed subtype save to leave an orphan parent record.
Prompt 05 — DRF Serializers, APIs, Filters
Create read/write serializers and production REST endpoints using established SIMS conventions. Validate required category and event_name, active foreign keys, country-state compatibility, dates, max lengths, normalized text, duplicate policy, and immutable fields. Support paginated list, retrieve, create, update, permitted archive/delete, workflow actions, search, sorting, and filters for category/date/organizer/organization/geography plus inherited employee/department/institution/academic-year/status fields. Optimize joins and prevent N+1 queries.
Prompt 06 — RBAC and Object-Level Security
Implement server-side permissions for staff owners, HoD/reviewers, institutional administrators, and system administrators according to the existing SIMS model. Scope records by authorized organization. Require explicit permissions for review, export, and master administration. Block mass assignment of staff_activity_id, employee ownership, institution, activity type, and approval state. Apply the same scope to attachments and reports. Add positive and negative permission tests.
Prompt 07 — Master Data Integration
Reuse cocurricular_category, organizer, external_organization, country, and state masters. Prompt 08 — React/TypeScript Mobile-First UI

Prompt 10 — PWA, Offline, and Security
