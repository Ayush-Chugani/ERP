How to use this pack
Run the prompts in sequence. Each stage assumes that earlier accepted outputs are available in the same working context. Review and commit one stage before moving to the next, especially where revised DDL, timetable lifecycle, or collision rules affect later code.
Attach or paste the current repository tree, relevant settings, and upstream model definitions before Prompt 1.
Ask the implementation agent to identify assumptions and wait only when a missing decision changes data integrity, scheduling semantics, or authorization.
Require runnable files, migrations, tests, commands, sample data, and verification evidence at every stage.
Keep institution scope server-controlled and treat allocation, scheduling, overrides, publication, and exceptions as auditable operations.
Use the final integrated build prompt only after the individual design decisions have been reviewed.

Common implementation context
Act as a senior full-stack Python web developer and software architect. Implement Module 8 of the SIMS platform as part of an enterprise plugin-ready modular monolith.
Use Django 5.x, Django REST Framework, MySQL 8.0.16 or later, React with TypeScript, Material UI, Vite, and @vite-pwa/plugin, with Gunicorn behind Nginx. The Django custom User model is the authentication authority. Retain the SIMS authorization extension for institution membership, scoped roles, campus and department scope, module activation, workflow authority, confidentiality, and record-level access.
Reuse the established institution, academic calendar, curriculum, student and staff, admission, and term-registration modules. Do not duplicate employee, room, time-slot, course, section, batch, or term masters. Derive ownership scope on the server, keep scheduling rules in explicit services, use transaction.atomic and select_for_update where changes can collide, and expose stable versioned APIs.
Cross-cutting invariants
No assignment, session, room, employee, section, batch, or time slot may cross institution scope through a client-supplied identifier.
A timetable session may reference only a faculty assignment for the same course-offering section and an intersecting active date range.
Published sessions must not create overlapping room, faculty, class-section, or class-batch occupancy.
Collision checks must compare time and date intervals, not only foreign-key equality.
Overrides, substitutions, cancellations, and published changes require authority, a reason, and an immutable audit trail.
Downstream attendance and notifications must consume committed published occurrences, never an unapproved draft.

CREATE TABLE faculty_course_assignment (
    faculty_assignment_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    course_offering_section_id BIGINT UNSIGNED NOT NULL,
    employee_id BIGINT UNSIGNED NOT NULL,
    assignment_role ENUM('PRIMARY_INSTRUCTOR','CO_INSTRUCTOR','LAB_INSTRUCTOR','TUTOR','COORDINATOR','OTHER') NOT NULL,
    workload_hours DECIMAL(6,2) NULL,
    start_date DATE NOT NULL,
    end_date DATE NULL,
    assignment_status ENUM('PLANNED','ACTIVE','COMPLETED','CANCELLED') NOT NULL DEFAULT 'ACTIVE',
    CONSTRAINT uq_faculty_course_assignment UNIQUE (course_offering_section_id, employee_id, assignment_role),
    CONSTRAINT fk_faculty_assignment_section FOREIGN KEY (course_offering_section_id) REFERENCES course_offering_section(course_offering_section_id),
    CONSTRAINT fk_faculty_assignment_employee FOREIGN KEY (employee_id) REFERENCES employee(employee_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
 
CREATE TABLE timetable_session (
    timetable_session_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    course_offering_section_id BIGINT UNSIGNED NOT NULL,
    faculty_assignment_id BIGINT UNSIGNED NULL,
    day_of_week TINYINT UNSIGNED NOT NULL,
    time_slot_id SMALLINT UNSIGNED NOT NULL,
    room_id INT UNSIGNED NULL,
    effective_from DATE NOT NULL,
    effective_to DATE NULL,
    CONSTRAINT chk_day_of_week CHECK (day_of_week BETWEEN 1 AND 7),
    CONSTRAINT uq_timetable_room UNIQUE (day_of_week, time_slot_id, room_id, effective_from),
    CONSTRAINT fk_timetable_section FOREIGN KEY (course_offering_section_id) REFERENCES course_offering_section(course_offering_section_id),
    CONSTRAINT fk_timetable_faculty FOREIGN KEY (faculty_assignment_id) REFERENCES faculty_course_assignment(faculty_assignment_id),
    CONSTRAINT fk_timetable_time_slot FOREIGN KEY (time_slot_id) REFERENCES time_slot(time_slot_id),
    CONSTRAINT fk_timetable_room FOREIGN KEY (room_id) REFERENCES room(room_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
