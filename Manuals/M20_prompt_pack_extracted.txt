Prompt 3  Implement external organization models
Implement external_organization, external_organization_type, organizer, publisher and funding_agency. Reference existing state and country records through ForeignKey with the exact database columns. Preserve nullable organization_code and the composite unique organization_name, city, country_id. Explain MySQL NULL semantics: the unique key does not prevent duplicates when city or country is NULL; propose a service level normalization and duplicate review workflow without silently changing the DDL. Model external_organization_type with its two column composite primary key where the project’s Django version supports it, or use an explicit compatible mapping/migration plan and explain ORM limitations. Organizer and publisher each have a unique organization link. funding_agency has a unique organization and required funding_type. Do not silently infer organization type membership; validate it in a service if the business requires that invariant.
Prompt 4  Migration and database integrity
Create dependency ordered migrations and document SQL produced on MySQL. Review SMALLINT, TINYINT and BIGINT UNSIGNED fidelity, Boolean mapping, TIMESTAMP default and ON UPDATE handling, collation, unique indexes, foreign key names and composite primary key support. If exact MySQL fidelity needs RunSQL, pair it with appropriate migration state operations and reversible SQL. Provide migration commands, a preflight query for existing tables and records, and a rollback strategy. Never generate destructive schema changes without an explicit data migration plan.
Prompt 5  Seed controlled vocabularies
Create an idempotent management command or data migration to load institution approved reference values. Seed values by stable code with update_or_create, do not reset primary keys, and preserve administratively edited descriptions unless a documented policy says otherwise. Provide illustrative values for publication, indexing, metric, activity, status and confidentiality categories clearly marked as proposals rather than official institutional definitions. Expose import validation, dry run, duplicate detection and a summary report. Test reruns and rollback behavior.
Prompt 6  Services and validation
Implement service functions for create/update/deactivate and resolve by stable code, with transactions for external organizations and role associations. Normalize surrounding whitespace, code case and URLs consistently while preserving display names. Validate state/country consistency if the existing geography module supports it. Reject references to inactive masters for new records but allow historical references to remain readable. Protect referenced rows against hard deletion; implement explicit deactivate/reactivate decisions with audit events and permission checks. Handle concurrent unique key conflicts cleanly.
Prompt 7  DRF API and authorization
Build paginated DRF list/detail/create/update endpoints for each master, grouped through a coherent router. Use the existing custom user permission model: authenticated readers may view authorized reference data, designated master data administrators may mutate it, and sensitive organization contact fields require the correct permission. Support active filter, exact code, safe text search and deterministic ordering. Validate requests in serializers and services; return stable error responses and proper 403, 404 and 409 behavior. Use select_related/prefetch_related for organization roles, country/state and funding type. Produce route and permission matrices and OpenAPI examples.
Prompt 8  Admin and mobile PWA screens
Register all masters in Django admin with search fields, filters, read only creation timestamps and controlled mutation permissions. Build React TypeScript mobile first screens for list, search, create, edit, deactivate and organization role assignment, consuming the DRF contract. Display validation errors, loading and offline states accessibly. Cache read only reference lists with versioned invalidation in the service worker; queue no master data writes offline unless conflict handling and authorization are designed. Keep an audit friendly confirmation for deactivation.
Prompt 9  Security and audit
Threat model mutation routes, bulk import, organization contacts and cross app reuse. Enforce server side permission checks, CSRF/session or token policy consistent with the existing stack, input limits and safe URL validation. Audit actor, timestamp, record ID, action and before/after values for changes; avoid logging secrets and unnecessary personal information. Ensure list APIs do not reveal restricted organization fields. Add rate limiting only where supported by existing infrastructure.
Prompt 10  Focused verification and handoff
Write meaningful tests for unique codes/names, nullable composite uniqueness behavior, foreign keys, organization roles, inactive selections, permissions, migration on MySQL, idempotent seed reruns and concurrency conflicts. Verify schema with SHOW CREATE TABLE and compare every supplied column, index and constraint. Check API query counts for organization lists and test a narrow mobile viewport. Provide commands run, results, remaining deviations, sample API requests and a completion checklist. Do not claim MySQL behavior from SQLite tests.
