FUNDED RESEARCH PROJECTS
Enterprise Django + MySQL + React/TypeScript PWA Implementation Prompt Pack
1. Purpose
This prompt pack is intended to guide an AI coding assistant through the complete implementation of Module 26 — Funded Research Projects in an existing enterprise SIMS. Use the prompts sequentially. Each prompt assumes Django + Django REST Framework, MySQL 8/InnoDB, React + TypeScript, and a mobile-first Progressive Web Application.
2. Core Domain
funded_research_project is a specialization of staff_activity and shares staff_activity_id as its primary key.
A funded project may optionally originate from research_proposal through source_proposal_activity_id.
The project references employee, department, funding_agency, funding_type, and research_status master entities.
research_project_financial_utilization is a one-to-many child entity used for period-wise financial reporting.
All money must use Decimal/DECIMAL(16,2); never use binary floating point.
All writes must be authenticated, authorized, validated, transactional, and auditable.
3. Recommended Schema Enhancements
Add indexes for source_proposal_activity_id, principal_investigator_employee_id, department_id, funding_agency_id, funding_type_id, research_status_id, sanction_date, project_start_date, and project_end_date.
Define a single authoritative strategy for project amount_received and amount_utilized so totals cannot drift from utilization records.
Consider validating closing_balance = opening_balance + amount_received - expenditure_amount, unless institutional rules explicitly permit adjustments.
Consider duplicate-period protection for financial utilization records.
Store sanction orders, utilization certificates, statements of expenditure, completion reports, and related evidence in the existing document subsystem rather than BLOB fields.
Use the platform audit framework for created/updated actor, timestamps, status changes, financial changes, and void/delete actions.
